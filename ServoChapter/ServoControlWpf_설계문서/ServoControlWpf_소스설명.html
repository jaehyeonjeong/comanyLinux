1. 읽기 전에 — 네 개의 층

이 프로그램은 MVVM(Model · View · ViewModel) 구조에 Services 를 더한 네 개의 층으로 나뉩니다. 층을 나눈 이유는 간단합니다. "서보를 아는 코드" 와 "화면을 아는 코드" 를 섞지 않으면, 화면 없이도 서보 코드를 테스트할 수 있고, 통신 방식이 바뀌어도 화면을 고칠 필요가 없기 때문입니다.

층폴더맡은 일비유
ModelServoControlWpf\Model\서보 사양·상태, pigpiod 와의 TCP 통신, WSL 터널, 설정 파일. 화면을 전혀 모른다.엔진과 배선
ServicesServoControlWpf\Services\wsl.exe 같은 바깥 프로그램을 실행하고 출력을 받아 오는 도우미외부 업체에 전화 거는 비서
ViewModelServoControlWpf\ViewModel\화면의 요청을 모델에 전달하고, 모델의 변화를 화면용 속성으로 바꿔 준다.운전석 계기판과 페달 사이의 통역
ViewServoControlWpf\View\, App.xaml창·다이얼·카메라 그림. 로직은 거의 없고 ViewModel 의 속성에 바인딩만 한다계기판과 핸들
왜 "아래 층은 위 층을 모르게" 하나 ServoModel 은 화면이 WPF 인지, 콘솔인지, 테스트인지 전혀 모릅니다. 그래서 테스트 프로젝트는 화면 없이 ServoModel 에 가짜 드라이버를 꽂아 "실패하면 이전 값을 유지하는가" 같은 규칙을 검사할 수 있습니다(8장). 반대로 MainWindow.xaml 은 TCP 가 뭔지 모릅니다. 연결 방식이 세 가지(직접·터널·에뮬레이터)여도 화면 코드는 한 줄도 다르지 않습니다.

3. Model 층 — 서보와 통신을 아는 부품

ServoSpec Model\ServoSpec.cs · record struct
역할: 서보 한 개의 "사양표" 와 각도 ↔ 펄스폭 환산.

쉽게 말하면 온도계의 눈금표입니다. "1500 µs 가 0°, 1900 µs 가 +40°" 라는 눈금을 들고 있다가, 각도를 주면 펄스폭을, 펄스폭을 주면 각도를 계산해 줍니다. 값이 바뀌지 않는 record struct 라서 복사해도 안전하고, 보정값을 바꿀 때는 새 ServoSpec 을 만들어 통째로 갈아 끼웁니다.

멤버하는 일
MinPulse / NeutralPulse / MaxPulse최소·중립·최대 펄스폭(µs). 기본 1100 / 1500 / 1900
MinAngle / MaxAngle / Gpio허용 각도(기본 ±40°)와 BCM 핀 번호(기본 18)
Hs311Official() · Hs311Extended()제조사 공식값(±40°) · 비공식 확장값(600~2400 µs, ±90°)
AngleToPulse(angle)중립을 기준으로 +쪽과 −쪽을 따로 비례 계산. 양쪽 기울기가 달라도(예 1100/1500/2100) 보정이 됨. 범위 밖 각도는 먼저 잘라 냄
PulseToAngle(pulse)반대 방향 변환. 펄스 슬라이더·입력칸이 각도를 바꿀 때 사용
IsValid()pigpio 허용 범위(500~2500), 최소<중립<최대, ±90° 이내, GPIO 2~27 검사. 보정값 적용 전에 반드시 통과해야 함

협력자: ServoModel(현재 사양 보관), MainViewModel(펄스 ↔ 각도 변환), AppSettings(저장·복원). 주의: 10 µs/° 라는 숫자가 코드에 직접 박혀 있지 않습니다. 모두 사양표로부터 계산되므로 다른 서보를 쓰려면 사양값만 바꾸면 됩니다.

IServoDriver Model\IServoDriver.cs · interface  ·  ServoException Model\ServoException.cs
역할: "펄스를 내보내는 장치" 라면 누구나 지켜야 하는 규격 + 실패를 알리는 예외.

쉽게 말하면 콘센트 규격입니다. ServoModel 은 콘센트(IServoDriver)에만 꽂고, 뒤에 실제 Pi 가 있든(RemotePigpioDriver) 아무것도 없든(SimulatedDriver) 신경 쓰지 않습니다. 이것이 Strategy 패턴이고, [연결]/[연결 해제] 는 사실 "드라이버 갈아 끼우기" 입니다.

멤버하는 일
Name · Info상태 표시용 이름("에뮬레이터 127.0.0.1:8888 · GPIO18")과 장치 정보("Pi 리비전 c03111 · pigpio v79")
IsRemote · IsLinkAlive원격 장치인지 · 통신 경로가 살아 있는지. ViewModel 의 "연결됨" 표시와 자동 해제 판단에 쓰임
Open(gpio)핀 준비. 원격이면 이때 TCP 접속
WritePulse(µs) · Release()펄스 출력 · 펄스 0(힘 빼기)
ReadPulse()장치가 지금 내보내는 펄스폭(µs). 0 = 꺼짐, null = 알 수 없음. 연결 직후 화면을 실제 서보에 맞추는 근거
ReleaseOnDisposeDispose 때 출력을 끌지(기본 true). false 면 접속만 끊고 서보는 마지막 펄스를 계속 받음("연결 해제 시 출력 유지")
ServoException.LinkLosttrue = 통신이 끊긴 오류(연결 정리 필요) / false = pigpio 가 명령만 거부(연결 유지). ViewModel 의 HandleFailure 가 이 값으로 갈림

주의: 실패를 반환값이 아니라 예외로 알립니다. 덕분에 "실패하면 상태를 바꾸지 않는다" 는 규칙을 try/catch 한 줄로 지킬 수 있습니다.

SimulatedDriver Model\SimulatedDriver.cs
역할: 아무 데도 보내지 않는 빈 드라이버. 프로그램이 처음 켜졌을 때와 [연결 해제] 뒤에 꽂혀 있다.

쉽게 말하면 플러그를 뽑아 둔 상태를 나타내는 "빈 콘센트 마개" 입니다. 14줄뿐이지만 덕분에 ServoModel 은 "드라이버가 null 인가" 를 어디서도 검사하지 않아도 됩니다(Null Object 패턴). 화면은 그대로 동작하므로 Pi 없이도 다이얼·슬라이더를 연습할 수 있습니다.

PigpioClient Model\PigpioClient.cs
역할: pigpiod 와 주고받는 16바이트 명령을 만들고 읽는, 가장 낮은 통신 층.

쉽게 말하면 외국어 통역사입니다. "GPIO18 을 1700 µs 로" 라는 요청을 pigpiod 가 알아듣는 16바이트(cmd=8, p1=18, p2=1700, p3=0, 각각 4바이트 little-endian)로 바꿔 보내고, 돌아온 16바이트의 마지막 4바이트(res)를 읽어 성공(0 이상)인지 오류(음수)인지 알려 줍니다.

멤버하는 일

9. 시나리오로 따라가기 — 버튼 하나가 지나가는 길

9-1. [연결] 을 눌렀을 때 (에뮬레이터 모드)

  1. MainWindow: 버튼의 Command → MainViewModel.ConnectToggleCommand
  2. MainViewModel.OnConnectToggleAsync: IsBusy=true(버튼 "연결 중…", 설정칸 잠김) → 모드가 Emulator 이므로 StartEmulatorDriver()
  3. PigpioEmulatorServer: 127.0.0.1:8888 에서 듣기 시작 → RemotePigpioDriver("127.0.0.1", 8888, server) 생성
  4. Task.Run(() => driver.Open(18)): PigpioClient.Connect → Command(HWVER) → 서버가 0xc03111 응답 → Command(PIGPV) → 79 → Info = "Pi 리비전 c03111 · pigpio v79"
  5. ServoModel.SetDriver(driver): 이전 SimulatedDriver Release·Dispose → 교체 → SyncFromDevice: driver.ReadPulse() → PigpioClient.Command(GPW, 18) → 서버가 기억한 펄스(예 1300) 또는 −93 → 1300 이면 Angle = −20°, 출력 켜짐 → Changed 이벤트
  6. MainViewModel.SyncFromModel: IsConnected=true 등 알림 → 버튼 "연결 해제"(초록), 상단에 장치 정보, 왼쪽 카메라 뷰의 IsConnected 가 true 로(막이 걷힘)

9-2. 다이얼을 +20° 로 돌렸을 때

  1. ServoDial.OnMouseMove: 마우스 방향 → ValueFromPoint → Value=20 → 양방향 바인딩이 MainViewModel.Angle 에 20 을 set
  2. Angle setter: _syncing 이 false 이므로 RequestAngle(20) → 스윕 정지 → ServoModel.SetAngle(20)
  3. ServoModel: Spec.ClampAngle(20)=20 → Spec.AngleToPulse(20)=1700 → RemotePigpioDriver.WritePulse(1700) → PigpioClient.Command(8, 18, 1700) → 16바이트 전송 → res 0
  4. 성공했으므로 Angle=20, IsOutputOn=true → Changed
  5. SyncFromModel(_syncing=true): Angle, Pulse=1700, PulseInput, IsOutputOn 등 알림 → 각도 줄 20.0, 펄스 줄 1700, 다이얼 힌트 "1700 µs · 출력 켜짐", ServoCameraView 는 목표 20° 를 향해 316 °/s 로 회전 시작, 상단 "가짜 Pi 수신 #3: SERVO gpio=18 1700 µs"

펄스 입력칸에 1650 을 넣으면 2번이 PulseInput setter 로 바뀔 뿐입니다: 범위로 자름 → Spec.PulseToAngle(1650)=15 → RequestAngle(15) → 이후 동일.

9-3. 통신이 끊겼을 때

  1. PigpioClient.Command: 1.5초 안에 응답이 없거나 상대가 끊음 → Abort() → ServoException(linkLost: true)
  2. 예외는 ServoModel.SetAngle 을 그대로 통과(상태 불변) → MainViewModel.RequestAngle 의 catch → HandleFailure
  3. LinkLost 이므로 OnDisconnect(): ServoModel.SetDriver(new SimulatedDriver(), releaseOld) → 출력 유지 옵션이 꺼져 있으면 이전 드라이버 Release(0.5초 재접속해 펄스 0 시도), 켜져 있으면 건너뜀 → Dispose(터널 종료; 에뮬레이터 서버는 유지)
  4. 오류 창: "Pi 응답 없음 (시간 초과) … 연결을 해제했습니다. 다시 [연결]을 눌러 주세요." 화면은 "연결 안 됨" 으로, 카메라 뷰는 그 자리에서 멈추고 막이 덮임

pigpio 가 명령만 거부한 경우(예 −7 PI_BAD_PULSEWIDTH)는 LinkLost=false 라 연결을 유지하고 메시지만 보여 줍니다.

9-4. 창을 닫았을 때

  1. App: window.Closed → ShutdownOnce() → MainViewModel.Shutdown()
  2. 스윕 정지 → AppSettings.Save()(주소·모드·스크립트 폴더 등) → WslViewModel.Cancel()(실행 중인 wsl.exe 종료)
  3. ServoModel.Dispose(releaseOutput) → RemotePigpioDriver.Dispose(): 옵션이 꺼져 있으면 Release()(SERVO gpio 0 = 힘 빼기), 켜져 있으면 건너뜀(서보가 자리를 지킴) → 소켓 닫기 → 터널 Dispose. 그 다음 _emuServer?.Dispose() 가 상태 파일을 저장
  4. 다음 실행: App 이 model.Start(spec, settings.LastDrivenAngle) 로 저장된 각도에서 시작 → [연결] → 9-1 의 GPW 로 장치 보고에 맞춰 확정
pigpiod 는 접속이 끊겨도 마지막 펄스를 계속 낸다 그래서 "끊기" 만 하면 서보는 계속 힘을 줍니다. 이 프로그램이 종료·해제·오류 때마다 굳이 펄스 0 을 보내려고 애쓰는(심지어 0.5초 재접속까지 하는) 이유입니다.

11. 용어 사전

용어뜻 (이 프로젝트에서)
MVVMModel(데이터·규칙) · View(화면) · ViewModel(둘 사이의 통역). View 는 ViewModel 의 속성에 바인딩만 하고 코드를 거의 갖지 않는다

Strategy / Null Object 패턴같은 규격의 부품을 바꿔 끼우는 것 / "없음" 을 나타내는 빈 부품(SimulatedDriver)
